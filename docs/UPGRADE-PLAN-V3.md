# V3 升级规划：主链路 AI 深度扩展

> 定位：六轮审查把可靠性推到头部水准后，竞赛权重 35% 的「AI 技术深度」与 25% 的「创新性」
> 还有可兑现空间。本规划不复述已知架构，只做**本次升级的三件事**：主链路 AI 能力扩展。
> 方法论与既有体系对齐：先落盘 → TDD（红-绿-重构）→ 每片自带验收断言 → 全量门绿 → 独立提交。

## 0. 为什么不是第七轮审计

审计边际收益已见底（六轮约 76 条，P0/P1 清零），继续找 bug 是表演。评委的追问点
（客观评价已给出）集中在两处：RAG 评估说服力（本轮前已补齐）、创新面无新增量。
本规划投的是后者。

## 1. 兼容矩阵（必须不破坏的既有契约）

| 契约 | 约束 | 本规划的尊重方式 |
|---|---|---|
| `POST /api/posts` 返回 `{id,status,matchedCount}` | 前端发布页依赖形状 | P1 只追加站内通知，**不改响应体** |
| `GET /api/ai/digest` 公开匿名可用 | 首页未登录也要出简报 | P3 新增 `?scope=personal`，默认行为与响应形状不变 |
| 消息中心 tab 白名单（comment/like/match/digest/system） | 前端过滤按此枚举 | P1 相似提醒复用 `system` 类型 + 明确文案，不加新类型 |
| 匿名可见性口径（作者/管理员可见、陌生人不可见） | 三处一致（列表/详情/RAG） | P2 推荐轨道与列表同口径 JOIN 过滤 |
| 封禁口径（`u.status != 'banned'`） | 全站统一 | P1/P2 候选查询同口径 |
| `/api/posts/:id` 路由参数切换重载（R4 修复） | 详情→详情跳转不残留 | P2 新轨道点击走同一 `router.push` 路径 |

## 2. 阶段切片

### P1 — 发布时相似帖检测（防重复刷屏，善意提醒而非拦截）

**动机**：校园墙真实痛点是同一内容反复刷屏（原实现零防御）。检测挂在发帖成功
之后：命中高相似已有帖 → 站内通知作者（复用 system 类型）——既防刷又保留用户自主决定权，
比直接拦截更「实用好用」（用户验收标准）。

- 相似度：归一化文本 bigram 集合 Jaccard；标题与正文分两路、0.5/0.5 加权
  （标题相同是最强重复信号）。复用 `utils/matching.ts` 的归一化风格但独立成函数，
  不污染雷达评分
- 候选限流：同板块最近 500 条先行收窄，再全库兜底一次，成本可控
- **评估门**：新增 `scripts/eval-similar-posts.ts`——构造「真重复对 / 同主题不同文 /
  无关对」标注集，选阈值使重复对全中且误报为 0，CI 可回归（与雷达/RAG 门同款纪律）
- 服务函数单测（阈值边界、空文本、超长截断）+ 集成回归（发帖触发通知 /
  无相似不发）+ E2E 不受影响（发布链路形状不变）

### P2 — 帖子详情「相关推荐」轨道

**动机**：阅读时长尾留存是信息流产品的基本盘；推荐由 P1 的服务函数直接派生（复用率最大化）。

- 位置：`PostDetailPage.vue` 评论区之后（人读到底的自然位置）
- 数据：`GET /api/posts/:id/similars`——排除自身/待审/删除/封禁作者；取 top6；
  每项含 id/标题/板块/赞数（最小字段集，不做整帖格式化）
- 交互：点击走现有 `router.push(\`/post/${id}\`)`（R4 路由复用修复自动受益）
- 断言：API 单元 + 集成（自身不返回、待审帖不给陌生人推荐、排序按相似度降序）

### P3 — 个性化每日简报

**动机**：首页「今日校园」是全站一条；登录用户的订阅板块与点赞轨迹不该与游客同一条。

- `GET /api/ai/digest?scope=personal`（authRequired）：订阅板块当日热点 + 近期互动
  话题，模板拼装保证零延迟零成本；`isAiUsable()` 时追加一句 LLM 人话化（沿用现有预算纪律，
  失败静默退回模板）
- 用户级 60s 缓存（Map<userId,{ts,data}>）+ 频控，复用 aiLimiter 实例
- 匿名/未登录仍拿全站版（默认行为不变）
- 断言：personal 路径契约（空订阅回退、互动聚合正确、缓存命中、LLM 失败降级模板）

## 3. 验收断言（每片交付即验）

| 断言 | 方法 |
|---|---|
| 相似检测不误报不漏报 | eval-similar-posts 门通过（阈值标定的量化证据入报告） |
| 发布链路形状不变 | E2E publish.spec 15→+1 通过（响应体字段回归） |
| 推荐轨道可见性一致 | 单测钉死排除集合（自身/待审/删除/封禁） |
| personal 简报降级链完整 | 单测钉死三态（缓存/LLM 失败/空订阅） |
| 零回归 | 全量 vitest + lint + check + Playwright 全绿；五 job CI 含 docker 门 |
| 数字同步 | 四文档 + PDF 随每片提交更新 |

## 4. 非目标（明确不做，防半成品）

- 向量化全站帖子（embedding 列迁移）——P1/P2 用词面相似度足够，做迁移是过度工程
- 小程序端适配（WEB 赛道，与后端共享契约，留待真实运营需求）
- 任何部署动作（用户明确暂不考虑）
