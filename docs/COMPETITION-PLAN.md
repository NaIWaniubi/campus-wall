# 冲第一名的作战计划

> 生成日期：2026-10-29
> 方法：6 路并行专家审计（赛事评委 / 产品增长 / 架构护城河 / 安全可靠性 / 体验路演 / 红队挑刺），
> 所有结论均带 `path:line` 证据或实测复现，不凭印象。

---

## 0. 一句话结论

**现状是「省一稳、国赛陪跑」，冲第一名的瓶颈不在代码量，而在三件事：可证明的运营数据、可复现的技术指标、可防守的匿名承诺。**

工程底子（双端 + 19 路由 + 撮合 + AI + 147 测试 + CI）已经超过绝大多数参赛作品，
但评委三分钟能验的三个动作——`clone` 后跑测试、点开某人主页、给陌生人打一星——原本全部见血。
本轮已把这三刀全部堵死（见第 2 节）。

## 3. 三个决定性差距（省一 → 国一）

### 差距一：没有真实用户与运营数据（权重最高，且无法压缩周期）

答辩第一问必然是「多少人在用、七日留存多少」。当前库中只有 1 个管理员 + 5 个演示号 + 6 个测试号，
19 条 published 帖全是 seed。**这一项不解决，前面所有技术分都是零乘数。**

必须今天就启动，因为审核周期不可压缩：

1. 注册正式 AppID → 提交小程序审核（预留 2–4 周）
2. 单校冷启动（见第 4 节日历）
3. 埋点补齐 `users.school / users.last_active_at / posts.audited_at / events` 四张/列

### 差距二：技术亮点没有可复现指标（**已补齐**）

「智能雷达」此前没有任何评测数字。现已落地 `scripts/eval-radar.ts`（21 组 query / 63 个候选标注集），
并在 CI 中作为回归门运行（`npm run eval:radar -- --gate`）。

**实测结果（本轮，可复现）**：

| 指标 | 雷达（复合特征） | 基线（纯关键词） | 说明 |
|---|---|---|---|
| P@1 | 100.0% | 19.0% | 首位推荐即正确答案 |
| P@3 | 100.0% | 19.0% | 前三条含正确答案 |
| MRR | 1.000 | 0.190 | 正确候选的平均排名 |
| 召回率 | 100.0% | 19.0% | 正样本过阈值比例 |
| 误报率 | 7.1% | 0.0% | 负样本被误推比例 |
| 精确率 | 87.5% | 100.0% | 推送结果里正确占比 |

**关键结论**：纯关键词基线几乎不误报，但只能召回不到两成——关键词写法不同就完全找不到；
雷达把召回拉到 100%，代价是 7% 的误报（推了同地点不同物品）。失物招领场景下
**漏报（找不到）比误报（多看一条）代价更高**，这个取舍是刻意的，答辩时要主动讲清。

标注集同时固化为 7 条对抗样本单测（`api/tests/unit/matching.test.ts`），覆盖：
只撞品类不算命中、地点不能单独构成命中、超时间窗硬过滤、双方无 itemType 时的权重自适应。

### 差距三：微信生态纵深几乎为零

`msgSecCheck` 未接（敏感词是手写词表）、订阅消息骨架已有但未跑通、`/auth/wx-login` 端点不存在
（`README` 宣称有、实测 404）。小程序赛道不用微信能力，等于自废主场优势。

## 6. 北极星与取证 SQL

**北极星指标：每日有效连接（评论 + 私信 + 出价 + 关注），D30 目标 ≥ 80/日。**

```sql
-- DAU（行为近似：库中无登录日志，用行为表并集）
WITH a AS (
  SELECT user_id u, date(created_at) d FROM posts
  UNION ALL SELECT user_id, date(created_at) FROM comments
  UNION ALL SELECT user_id, date(created_at) FROM likes
  UNION ALL SELECT user_id, date(created_at) FROM favorites
  UNION ALL SELECT sender_id, date(created_at) FROM chat_messages
)
SELECT d, COUNT(DISTINCT u) dau FROM a GROUP BY d ORDER BY d DESC;

-- 交易闭环率（必须双侧才算真闭环）
SELECT COUNT(*) AS trade,
       SUM(json_extract(extra_fields,'$.soldAt') IS NOT NULL) AS sold,
       SUM(json_extract(extra_fields,'$.soldTo') IS NOT NULL) AS two_sided
FROM posts WHERE section_id = 1 AND status != 'deleted';

-- 雷达可用性：有多少失物帖能找到 ≥1 条匹配
-- （需配合 scripts/radar-eval 跑批，见动作 2）
```

## 11. 答辩最可能被追问的 10 个安全问题（含标准回答要点）

1. **`admin/admin123` 从哪来？** 仅开发/测试环境播种；生产强制 `ADMIN_INITIAL_PASSWORD`，缺失即拒绝启动。
2. **通知为什么用全局广播？** 已改为按 `user_id` 定向 `sendTo`；主题订阅不再承载通知。
3. **改密/封号后旧 JWT 还能用 7 天？** 已知缺口，下一步加 `token_version` 或黑名单（当前未实现，如实回答）。
4. **限流取 `req.ip` 可伪造？** `trust proxy` 默认关闭，XFF 不生效；桶 key 不含 UA；另有学号维度与 IP 兜底桶。
5. **匿名帖编辑为何不重校验？** 已修：未传保留原值，显式变更复用创建侧 `force_anonymous` 与信誉门槛。
6. **没参与交易的人能给卖家扣分？** 已修：只允许交易双方，卖家不得指定非本单买家。
7. **`section_admin` 权限边界在哪？** 已收归：AI 知识库/模型配置改为 `superAdminRequired`。
8. **单条 SQLite 的 QPS 上限？** 读走 LRU + FTS5，写单线程 WAL；演示规模足够，横向扩展需改 PostgreSQL（已有脚手架但业务未接入）。
9. **401/403 为何返回 200？** 已修为真实状态码；`body.code` 保留业务码供前端区分。
10. **30 词敏感词库如何覆盖谐音/图片？** 手写词表只是前置快筛；`msgSecCheck` 文本机审 + `mediaCheckAsync` 图片异步送审已接入（2026-11-17），未配置微信凭据时自动降级为纯词表。

补充两条高频追问：
11. **封禁用户还能用旧 token 发消息吗？** REST 侧已拦；WS 侧本轮补上（`authJwt` 回查 `users.status`，角色也以库为准）。改密后旧 token 仍有效是已知缺口。
12. **Web 端发的失物帖能进雷达吗？** 本轮补上方向字段与必填校验；此前 Web 表单缺 `direction`，雷达与「丢失/拾获」双 Tab 都不会收录。
