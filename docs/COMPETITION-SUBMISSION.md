# 校园墙 · 参赛提交材料（TRAE 好应用大赏）

## 1. 一句话介绍

**校园墙**是一个面向高校的双端校园社区：Web（Vue3 + TS）+ 原生微信小程序（28 页），8 大板块覆盖二手交易、失物招领、表白墙、吐槽树洞、互助问答、校园活动、拼车、组队，并内置**失物智能雷达**、**信誉分体系**与**匿名治理闭环**。

V3 起它不再是「又一个绿白校园墙」：视觉换成**紫→品红→珊瑚的多巴胺青春体系**，产品把 AI 放进「发帖 → 读帖 → 看今天」主链路（**AI 一键成稿 / AI 划重点 / 今日校园简报**），并且每个 AI 能力都带**离线规则兜底 + 熔断**——模型挂了功能不挂，这是「耐用」的定义。

## 2. 三个能被评委三分钟内验证的记忆点

| 记忆点 | 怎么讲 | 证据 |
|---|---|---|
| **失物智能雷达** | 发一条「捡到校园卡」，系统自动匹配方向相反、品类一致的求助帖 | 离线评测：P@1 100% vs 纯关键词基线 19%，MRR 1.000，CI 里跑 `npm run eval:radar -- --gate` 做回归门 |
| **匿名是真的匿名** | 匿名帖不能按作者反查、编辑不会脱匿名、列表缓存不串号、封禁后旧 token 立刻失效 | 32 项安全加固逐条落在代码里（`api/routes/posts.ts`、`api/utils/jwt.ts`） |
| **治理闭环** | 发布→审核→举报→处理→审计留痕，全部可后台看到 | 后台数据总览：待审内容、待处理举报、审核通过率、7 日趋势 |

- **演示封面图**：12 张极光渐变海报（SVG→sharp JPEG，均 13–25 KB，共 288 KB），按板块主题定制（iPad/自行车/资料/校园卡/钥匙/表白/雨伞/晚会/招新/顺风车/自习/食堂），`node api/scripts/gen-demo-covers.mjs` 可重新生成；种子灌入时自动复制进上传目录并挂到 15 个演示帖上——信息流从纯色块变成有图卡片，部署包首启自带

- 上传文件 Content-Type 修正（demo jpg 曾被误标 `image/jpg`→现按扩展名精确映射 png/jpeg/webp）

## 11. 答辩预设 Q&A

**Q：有真实用户吗？**
A：目前是单校冷启动阶段，演示库为 5 个演示账号 + 20 帖，覆盖 8 个板块与全部闭环路径；我们有 30 天单校地推日历与北极星指标（每日有效连接 ≥80/日），可直接展示增长台账。

**Q：雷达的 100% 是不是过拟合？**
A：评测集是 21 组 query / 63 个候选的人工标注集，基线是纯关键词匹配（P@1 19%）。雷达把召回从 19% 拉到 100%，代价是 7.1% 误报（推了同地点不同物品）；失物场景下漏报比误报代价高，这个取舍是刻意的，脚本入库到 CI，任何人都能重跑。

**Q：匿名安全怎么保证？**
A：四道锁——列表接口对非本人强制 `is_anonymous = 0`（不能按作者反查）、编辑不传 `isAnonymous` 时保留原值、缓存 key 带查看者可见性维度（游客结果不会命中作者结果）、改密/封禁递增 `token_version` 让旧 token 立即失效。

**Q：为什么不用现成的框架/低代码？**
A：项目本身就是用 TRAE 从 PRD 到代码一路做出来的（`.trae/documents/` 保留 PRD 与技术架构文档），469 个测试 + 15 条浏览器 E2E、OpenAPI 3.1、CI 多道门（含 AI 护栏评估门与反向回归组）与严格类型都是在这条链路里长出来的。

**Q：为什么说「颠覆以往校园墙」？**
A：两处硬差异。①视觉：校园墙长期被「绿白 + 信息流堆卡片」框住，我们把主色换成青春紫、八板块八色相，并把 AI 卡片做成首屏第一块内容；②产品：传统校园墙的 AI 是角落里的客服，我们的 AI 在发布、阅读、浏览三条主路径上都有明确产出（成稿/划重点/简报），且每个产出都有规则兜底——评委断网也能看到完整效果。

**Q：AI 是贴上去的吗？**
A：不是，三个入口都改的是主链路：发布页没有 AI 时用户要手写标题正文选板块填价格（4 步），有 AI 时 1 句话；详情页的「划重点」直接复用正文做抽取式摘要，并叠加风控词规则；首页简报是服务端聚合 + 60s 缓存，不依赖前端算力。AI 只是把已有数据讲得更好，不产生新的数据依赖。
